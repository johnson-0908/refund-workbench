# 一键自动验收与公网 UI 演示

## 1. 运行

先启动本地 Docker Engine / Docker Desktop（Linux containers，建议至少 4 GiB 可用内存）。安装 Python 3.11+、Git；Windows 使用 PowerShell 7，Linux 使用 Bash 4+。

在项目根目录执行：

```sh
python scripts/verify.py
```

Linux 若 Python 命令为 `python3`，改为 `python3 scripts/verify.py`。Windows 也支持 `./scripts/verify.ps1`。首次拉取锁定基础镜像、npm/Go 依赖需要网络；之后允许复用构建缓存，没有要求删除缓存。构建环境与正式 Dockerfile 完全一致，不用宿主 Go/Node。

该入口不是 CI 的别名，不自动提交/推送/部署。只检查此刻磁盘上的已保存源码，包含尚未提交的修改；生成各文件 SHA256 清单以追溯本轮。未保存的编辑器内容不在范围内。

## 2. 自动执行内容

1. 拒绝远程 Docker；要求随机 `refund-deploy-test-auto-*` 项目没有任何已有容器、网络或卷。
2. 复用公开源码白名单/秘密预检，对同一份字节做快照，运行脚本守卫单测；运行秘密仍只存 ignored 私有目录。
3. 复用一键启动，随机密码、空闲本地端口，从源码构建并等待五服务健康。仅 Web 发布 loopback 端口。
4. 拓扑/数据库初态验证通过后，使用真实 Cookie + Origin + CSRF 调用 Nginx/API；读取 MySQL 只读快照核实业务和渠道结果。
5. 10 个同键并发及 16 个不同键并发；A-1002 为 UNKNOWN 时真实重启后端，再查询原渠道；验证失败、越权、当前企业恢复、六表归档、另一企业不变、Kafka→Redis 事件与旧事件屏障。
6. 前端构建阶段镜像执行 Vitest；组件测试使用 jsdom 与模拟 API，包含加载/错误/空态、首屏登录、切换/迟到请求、重试原意图等。生产构建已经执行 TypeScript 检查。
7. 在本轮独立 MySQL 内新建 **refund_test**（存在即失败，不覆盖），只向它授予本轮用户权限。Go 测试容器共享该 MySQL 的网络命名空间，使用 loopback 连接，满足原有测试安全白名单；Redis/Kafka 仍是本项目私网实例。执行 Go 集成、vet、build。真实依赖缺失/SKIP 均失败。
8. 输出报告，默认只停止本轮 Compose 容器，不删除业务卷、配置或证据。

容器 HTTP 验收针对本轮独立部署的 `refund_demo`；Go 集成针对同一独立实例中的 `refund_test`。**不是开发环境现有的同名数据库。** 不运行旧三组共享 `refund_acceptance` 的进程脚本，也不并发使用那套环境；旧完整回归仍见 `scripts/test.ps1`。

## 3. 九项清单对应证据

|项|自动验证层与业务断言|只操作公网 UI 能否完整验证|
|---|---|---|
|① 正常退款|A-1001 19900 分成功；API/SQL/渠道唯一且金额一致；金额/状态组件显示测试|只能看到页面成功和金额，不能核实 SQL/渠道|
|② 重复提交与异参冲突|同键同参返回原退款；改原因/改订单 409；前后金融快照不变|不能；需控制请求头中的原幂等键|
|③ 并发与换键提交|新订单上 16 个不同键同发，1 个创建、15 个明确 409；1 业务记录/1 渠道受理，submit_calls=effect_count=1|不能；需并发脚本，按钮连点不等价|
|④ 结果未知与原单查证|UNKNOWN→SUCCEEDED；退款 ID、渠道请求号不变，只 Query、不再 Submit|可演示状态变化；渠道提交次数需 SQL|
|⑤ 进程重启后恢复|UNKNOWN 时重启后端及进程内模拟器，状态/原记录仍在，查询收敛|需服务器重启配合，刷新浏览器不是进程重启|
|⑥ 明确失败与非法状态|A-1003 FAILED 有原因、换键仍拒绝；A-1004 无渠道记录|可演示失败/未支付禁操作；渠道零记录需 SQL|
|⑦ 权限与商户隔离|真实 API：匿名 401、只读写入 403、跨商户订单及退款 404|仅能演示角色/列表，隐藏按钮不证明防越权|
|⑧ 前端交互与切换身份|组件/组合逻辑：加载/空态/错误/处理中、身份切换、旧请求迟到不覆盖|正常切换可测；断网/延迟响应需 DevTools/自动测试|
|⑨ 干净环境可启动|源码锁定构建、随机新项目空卷、五服务健康、所有关键自动业务测试可运行|不能用已有在线站点证明从零启动|

PASS 只表示本表注明的自动验证层通过，不等于公网真浏览器端到端验证、面试官签收、真实支付认证或生产安全审计。

## 4. 结果与故障诊断

每轮独立输出 `evidence/checklist-<时间-随机值>/`：

- `report.html`：直接用浏览器打开的中文清单，无 CDN、无外部脚本。
- `report.json` / `report.md`：整体结果、阶段、覆盖边界与计数。
- `deployment.json`：真实 HTTP/SQL 断言、归档/数据版本、160 请求/并发 8 的小数据量只读基线（不外推生产 SLA）。
- `frontend.json` / `go.json`：具体测试结果；Go 数量包含子测试，不与顶层测试数量混淆。
- `source-manifest.json`：本轮公开源文件 SHA256；不是 Git 提交或镜像发布证明。
- `command-*.log`：本机分阶段日志，随机数据库密码脱敏；仍视为私有，禁止上传公开仓库。

仓库另提供经字段白名单导出的 [公开脱敏执行日志](TEST_EXECUTION_2026-10-29.md)，保留真实测试名称、结果、耗时及 SKIP；不复制原始 stdout/stderr、配置、路径、会话或请求响应，不改变上述私有文件的忽略规则。

退出码 0 表示本入口通过，非零表示失败/中断。没有执行到的清单项目为 NOT_RUN；失败断言为 FAIL。辅助 Python 守卫中的真实文件 symlink 创建测试在不支持该能力的 Windows 上可能 SKIP，报告单独列出、不计通过；Go/前端及真实业务场景不得以 SKIP 充数。

配置在 `.runtime/checklist-<同轮ID>/source/.runtime/`。失败时保留卷/现场与成功前的断言：先看 report.json 中失败阶段，再看对应日志。端口被竞争、镜像下载失败、Docker 资源不足都不会触发删除旧卷或停止其他项目。修复原因后重新执行会生成另一独立轮次，不覆盖失败证据。

需要查看本轮页面可用 `--keep-running`。站点是测试结束后的状态（A 已恢复后重新退款，B 已退款），不是未经操作的初态。想保留或删除旧轮次的卷由操作者确认后管理，脚本不自动清理。成功运行会移除自己的临时工具测试容器，保留本轮 Compose 数据与本地测试镜像。

尚未涵盖：公网真实浏览器视觉/网络条件、全新宿主安装 Docker 的体验、Go race detector、完整旧进程验收矩阵、依赖漏洞扫描、真实支付/IdP/TLS/HA/大规模容量。正式回归/发布仍需相应 CI、人工首屏和 Git index 公开检查。

## 5. 公网手动演示顺序

先确认演示记录可被恢复，再用 A 经办的“恢复初始数据”并输入精确确认文字（仅当前企业）。然后：

1. 退出后重新登录 A 经办，**不刷新页面**，应直接显示 4 笔订单。
2. A-1001 申请退款，成功、¥199.00。
3. A-1002 申请，显示待确认；查询原退款后成功、¥88.00。
4. A-1003 申请，显示明确失败及原因；不能再申请第二笔。
5. A-1004 未支付，申请不可用。
6. 切 A 查看身份：仍可查看 A 订单，不能申请/查证/恢复。
7. 切 B 经办：旧 A 订单立即清空，只加载 B-2001，金额 ¥256.00。

这主要演示 ①④⑥ 与 ⑦⑧ 的 UI 部分。②③⑤⑨ 以及 API 防越权、SQL/渠道一致性使用自动报告补充，不要仅凭 UI 把整项打勾。
